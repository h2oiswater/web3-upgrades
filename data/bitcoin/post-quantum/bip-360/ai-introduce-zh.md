# BIP-360 AI 解读

## 一句话总结

BIP-360 提出了一种新的比特币输出类型 **P2MR（Pay-to-Merkle-Root）**，通过移除 Taproot 的量子脆弱 keypath，让用户能用脚本树以抗量子方式持有比特币。

---

## 核心要点

### 🔐 问题：量子计算机威胁

比特币目前使用的椭圆曲线数字签名（ECDSA/Schnorr）基于**离散对数难题**。但量子计算机运行 **Shor 算法** 能在多项式时间内破解这个难题：

- 理论上需要约 **10⁸ 次操作** 就能恢复 256-bit 私钥
- 一旦量子计算机达到这个算力，所有暴露过公钥的比特币都可能被盗

### 🛡️ 解决方案：P2MR 输出类型

P2MR = P2TR（Taproot）去掉 keypath spend，只保留 script path

| 特性 | P2TR (当前) | P2MR (提议) |
|------|-------------|-------------|
| 地址前缀 | `bc1p` | `bc1z` |
| SegWit 版本 | v1 | v2 |
| keypath spend | ✅ 有（量子脆弱） | ❌ 无（安全） |
| script path | ✅ 有 | ✅ 有 |
| 支持 tapscript | ✅ | ✅ |
| 支持叶子脚本 | ✅ | ✅ |

### 🎯 关键设计

1. **无内部公钥**：P2MR 输出只提交到脚本树的 Merkle root，不提交内部公钥
2. **只有 script path**：必须通过脚本路径花费，没有直接的签名路径
3. **兼容现有 tapscript**：所有现有的 tapscript 程序无需修改即可使用
4. **软分叉升级**：通过 SegWit v2 实现，向后兼容

### ⚠️ 重要区分

BIP-360 只防御 **long exposure attack**（长期暴露攻击）：
- ✅ 已上链的公钥有足够时间被量子计算机破解
- ❌ 不防御 short exposure attack（短期暴露攻击）：内存池中的交易公钥暴露时间太短

防御短期攻击需要未来的 **后量子签名方案**。

---

## 为什么重要

1. **用户有需求**：政府和机构要求 2030-2033 年后量子升级，用户担心量子威胁
2. **渐进式防御**：不需要等完美的后量子签名，先用简单方案获得基础保护
3. **为未来铺路**：P2MR 输出可以兼容未来的后量子签名 opcode
4. **最小改动**：复用现有的 Taproot 代码，降低实施风险

---

## 现实影响

- 用户可以选择把资金从 `bc1p`（P2TR）迁移到 `bc1z`（P2MR）获得抗量子保护
- 钱包只需支持 script path spend（用 `OP_CHECKSIG` 叶子脚本）
- 交易 witness 比 P2TR keypath 大 37 字节，但比 P2TR script path 小 32 字节

---

## 一句话

> BIP-360 是比特币的"量子保险"——在完美的后量子签名到来之前，先给用户的脚本树加一把锁。🔐
