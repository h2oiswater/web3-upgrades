# BIP-141: 隔离见证 (SegWit)

## 一句话总结
把签名数据从交易中 "隔离" 出来——消灭交易延展性，变相扩容，并为未来的软分叉升级铺路。

## 核心解读

### 🔑 问题：签名是 "验证数据" 不是 "状态数据"
比特币的交易结构里，签名(scriptSig)和脚本混在一起。这导致：
- **延展性**：签名格式一变，txid 就变（BIP-66只解决了一部分）
- **浪费空间**：签名占交易大小的 60%+，但不影响UTXO状态
- **升级困难**：新功能需要所有节点同时升级（硬分叉）

### 🛠️ 方案：把签名 "隔离" 到 witness 结构
- **新的 witness 字段**：存储签名和脚本，不进入 txid 计算
- **新的地址格式**：P2WPKH（ witness program = 20字节），P2WSH（32字节）
- **脚本版本号**：Version 0 开始，未来可加 Version 1、2...
- **区块重量**：`Base size × 3 + Total size ≤ 4,000,000`
  - base：不含 witness 的大小
  - total：含 witness 的总大小
  - 相当于： witness 数据只算 1/4 权重

### 📊 影响
- **延展性消灭**：签名改变不再影响 txid
- **有效扩容**：区块容量从 1MB 提升到约 1.6-2MB（取决于 witness 比例）
- **Script versioning**：未来软分叉只需增加 witness version，无需新地址格式
- **闪电网络基石**：解决了 HTLC 的 txid 预测问题
