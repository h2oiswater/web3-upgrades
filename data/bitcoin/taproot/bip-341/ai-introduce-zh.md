# BIP-341: Taproot

## 一句话总结
让 "单签" 和 "多签/脚本" 在链上看起来完全一样——用一棵默克尔树隐藏所有未使用的花费条件。

## 核心解读

### 🔑 问题：脚本暴露隐私
以前的 P2SH 和 P2WSH：
- 花费时必须揭示完整脚本
- 所有花费条件（包括未使用的）都暴露在链上
- 攻击者可以分析脚本的常见模式，降低隐私

### 🛠️ 方案：Taproot = 公钥 + 默克尔树
每个 Taproot 输出对应一个组合：
- **内部公钥（Internal key）**：一个普通的公钥，可以 key path 直接花费
- **脚本树（Script tree）**：一棵默克尔树，叶节点是各种脚本条件

构造方式：
1. 取内部公钥 P
2. 取脚本树的根哈希
3. 计算 `Q = P + hash(P || merkle_root)·G`
4. 输出的 witness program 就是 Q 的 x 坐标

### 📊 两种花费路径
- **Key path**：直接 Schnorr 签名，看起来就是一个普通支付
- **Script path**：揭示使用的脚本 + 默克尔路径证明，只暴露实际使用的那个脚本

### 🔑 隐私提升
- 如果所有参与者合作，用 key path 花费——**看起来跟普通单签一模一样**
- 如果用 script path——只暴露使用的那个脚本，其他脚本仍隐藏
- 不同协议的 Taproot 输出无法区分
